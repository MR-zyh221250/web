# 双站业务版（2026-09-04）

## 访问与角色

- 展示站：https://neon-loft-zyh.duckdns.org/ 。非 3D、手机自适应、中英文界面与广告内容。
- 平台管理后台：https://crm.neon-loft-zyh.duckdns.org/ 。管理员和销售员从此登录，原 `/manage.html` 跳转至此。
- 商户工作台：https://merchant.neon-loft-zyh.duckdns.org/ 。仅店铺管理员登录。
- TeamCity：https://neon-ci-zyh.duckdns.org/ 。与业务账号独立。

管理员保留原账号和密码，管理客户、销售、店铺账号、店铺、广告审核和预约。销售员只访问自己负责的客户、销售和关联预约。店铺管理员由总管理员创建账号；首次登录修改临时密码，然后填写资料自行开店，每个店铺账号可自行开设一家店铺。店铺只能管理自己店铺的广告、预约、回复和成交记录。

客人在展示站自行注册，填写账号、姓名、联系电话和密码。注册会同时创建 CRM 客户记录，默认分配给最早建立且启用的管理员，之后可分配给销售员。店铺管理员不是客人；销售记录关联客户，可选关联店铺和广告；从预约登记成交时自动带入客人、店铺和广告，不自动生成付款记录。

## 操作流程

1. 平台管理员只在“账号管理”创建店铺管理员账号，另行交付临时密码；客人不能被设置为店铺负责人。
2. 店主使用该账号登录商户工作台，修改密码，再点击“我要开店”填写店名、双语介绍、地址、电话、微信。平台管理员的“店铺管理”用于审核后续业务及维护已有店铺，不代替店主开店。
3. 在“业务广告”新增广告：中文和英文标题、中文和英文正文、分类、图片、到期日期。上传支持 JPG/PNG/WebP，先在线裁剪再上传，最多 6 张，第一张为封面，可调整封面。
4. 保存草稿，或提交审核。提交审核必须提供两种语言的标题、正文和至少一张图片。详情为正文与多张图片组合，不接受任意 HTML。
5. 管理员查看双语内容和图片，审核通过或填写不通过原因。通过后前台可搜索、按分类筛选、进入图文详情。管理员可置顶或取消置顶。
6. 已发布广告编辑后重新审核；店铺可下架。到期日以北京时间当天结束为界，过期后列表、详情、图片和新预约均不可访问；不依赖后台页面保持打开。
7. 客人登录后点击“预约 + 留言”，选择未来 180 天内的时间并留言，在“我的预约”查看状态、店铺回复或取消预约。
8. 店铺确认或取消预约、填写回复；确认后可点击“确认成交”，录入成交项目、金额和日期。系统将预约标记为已完成，并生成关联客人、店铺和广告的成交记录。同一预约最多生成一笔成交；已完成和已取消的记录保留。
9. 客人登录前台后，右上角显示头像或姓名首字；点击进入个人资料，可选择 JPG/PNG/WebP、拖动和缩放裁剪后上传，也可移除头像。头像与同一条 CRM 客户记录关联，CRM 工作人员仍可在客户编辑弹窗维护头像。退出会删除服务器会话。

分类初始提供餐饮美食、购物零售、休闲体验、生活服务；管理员在“广告分类”新增、修改中英文名称及排序（0～9999，越小越靠前）。未使用的分类可以删除，已被广告使用的分类不可删除。前台及店铺表单同步读取分类。店铺名称/介绍支持双语，未填写英文时回退中文；广告发布时中英文均必填。

## 数据与权限

保留 users、sessions、customers、sales；增量增加 shops、adverts、media、customer_avatars、customer_accounts、reservations。用户角色扩展为 admin / sales / shop / customer。不删除原有业务数据。

图片先由浏览器裁剪为 JPEG，再由服务器 sharp 解码、去元数据和压缩，统一输出 JPEG，禁止 SVG/HTML；单图服务器保存上限 1 MB，输入像素上限 2000 万，每账号每日最多上传 200 次。图片二进制保存在 MySQL，现有 SQL 备份会包含图片。客户头像只对有权读取客户的后台账号开放，广告图片仅在关联广告审核通过且未过期时公开。未附着的上传图片仍保留，后续可按业务规模增加定期清理。

所有写操作校验来源；平台后台、商户工作台与展示站分别使用主机级 HttpOnly/Secure 会话 Cookie。登录接口同时校验访问域名与账号角色，商户不能在平台后台登录，管理员和销售员也不能在商户工作台登录。前台反向代理仅开放客人接口和公开广告接口，管理接口只在两个独立后台域名开放。数据库仍无公网端口。

## 构建与部署

`Dockerfile` 构建两个目标：默认 runtime 是展示站；crm 目标是管理站。两个独立 Nginx 容器监听宿主机回环地址 8080 / 8081，API 仍为 3000。站点不再加载原 3D 模型、纹理和视频包；旧源码保留在仓库供追溯。

流水线构建前台、管理站与 API 镜像；在临时 MySQL 中运行原 CRM 测试及 `backend/market-test.mjs`，测试权限隔离、审核、双语、搜索、过期、客人注册、预约回复、头像访问与登出。部署前 SQL 备份，随后更新 API、管理站、展示站和 Caddy。失败尝试恢复旧镜像、旧 Origin 和代理配置；数据库增量表保留，不做破坏性回滚。

可信 TeamCity Agent 须额外挂载 `/opt/neon-proxy:/opt/neon-proxy`，用于发布经版本控制的 Caddyfile。修改代理前保存备份，验证后重启。原 Docker socket 权限与专用 Agent 策略不变。

手动恢复时应使用对应版本镜像，并同步 `NEON_PUBLIC_ORIGIN`（平台后台）、`NEON_MERCHANT_ORIGIN`（商户工作台）、`NEON_FRONT_ORIGIN`（展示站）和 Caddy 路由。不要删除 MySQL 或 Caddy 证书持久卷。

本地 QA：`NEON_QA=1 npm run dev` 仅用于连接隔离测试 API（本机 3000），开发代理将 Origin 设置为 `http://test.local`；该开发设置不进入生产静态构建。

## 范围

### 预约与销售关联

- 预约确认本身不自动计入销售额。实际成交后，店铺管理员可在自家“预约与留言”点击“确认成交”，平台管理员或该客人的负责销售员也可点击“登记成交”，填写项目、金额和日期。
- 客人、店铺、广告从预约自动带入，不可更换。只有已确认或已完成的预约可转销售，待确认及已取消的预约不可转换。
- 同一预约最多关联一笔销售，重复提交会被拒绝；预约列表显示“已转销售”，销售列表显示来源及店铺、广告。
- 成交金额、项目和日期可更正。删除销售后可以重新登记，不会删除预约或自动修改预约状态。
- 手动销售可只关联客人，也可选店铺和该店铺已发布、未到期的广告；服务端检查店铺与广告匹配。原有历史关联在店铺停用或广告过期后继续保留。
- 店铺账号只能查看由自家预约或关联自家店铺产生的成交，不获得 CRM 客户资料、其他店铺成交、销售编辑或手工录入权限。平台管理员和销售员继续使用完整的 CRM 销售功能。
- 新增 advert_categories、sale_links 两张表，保留历史销售。数据库重启不覆盖已修改的分类名称和排序。
- 流水线增加 commerce-test.mjs，验证分类权限、双语同步、删除保护、销售关联、预约状态和重复转换。

当前实现预约与留言、店铺确认和回复，不包含支付、短信通知、自动翻译或客户原始 E-R 题中的课程检票系统。前台不会自动发布测试数据；真实广告由店铺提交、管理员审核后出现。
